# Nowlert CE v3.1.6 release notes

Nowlert CE v3.1.6 is a release-automation maintenance patch that completes the
Community Edition Stage-final workflow consolidation. It preserves v3.1.x
runtime behavior while reducing the active GitHub Actions surface and making the
Development and release-publication paths explicit inside their owning
workflows.

It keeps database schema **9** and the **`platform_database_v1`** configuration
model. No database migration is required from v3.1.5.

## Highlights

### Three-workflow CE release model

The active CE release path remains:

```text
Development -> Stage -> main -> Release
```

The default branch now contains exactly three release/CI workflows:

- **Continuous Integration** — tests every candidate and, after a green push to
  `development`, directly builds, verifies, publishes, and deploys the immutable
  Development image;
- **Promote CE to Stage** — runs the complete notification-silent gate, deploys
  the exact Development digest to Stage, verifies health/passive smoke, records
  desired state, and advances `stage`; and
- **Finalize CE Release** — validates Development/Stage evidence, live Stage and
  ledger state, publishes stable GHCR/Docker Hub aliases from the approved
  digest, then creates the annotated tag and GitHub Release.

There is no standalone Development Image workflow and no standalone Docker
Release Aliases workflow. Those responsibilities are now part of Continuous
Integration and Finalize CE Release respectively.

### Immutable promotion contract retained

- Development builds the candidate exactly once.
- Stage receives that exact immutable digest without rebuild.
- `main` advances only to the exact Stage-approved source commit.
- Release finalization requires `main == stage == source commit`.
- Stable `3.1.6` and `latest` registry aliases are copied from the approved
  digest with `skopeo`; no image rebuild is performed from the release tag.
- The finalizer validates the successful `development` **Continuous
  Integration** push run as Development evidence, together with the successful
  Stage promotion run.

## Compatibility

- Database schema: **9**
- Configuration model: **`platform_database_v1`**
- Persistent state path: **`/nowlert/state`**
- Python: **3.13**
- Existing v3.1.5 state can be used directly.
- Existing `NOWLERT_*` environment variables and `/api/v2` management contract
  remain unchanged.
- Event ingestion, parsers, routing, destinations, authentication, backups, and
  WebUI behavior are unchanged by this maintenance release.

## Upgrade from v3.1.5

1. Record the currently running image/version and immutable digest.
2. Retain a matched backup of `config`, `state`, and external `secrets` before
   deployment.
3. Pull/pin `theriark/nowlert-ce:3.1.6` or the published immutable digest.
4. Redeploy with the existing `/nowlert` mounts unchanged.
5. Verify `/api/health` reports `3.1.6`.
6. Verify normal login, routes, destinations, Delivery History, Audit Log,
   Users, and Backups.

## Release provenance

The v3.1.6 candidate is version-complete on `development` before Continuous
Integration builds the Development image. A successful `development` CI run
produces one immutable GHCR digest, verifies the packaged version/artwork, and
deploys that same digest to CE Development.

Stage promotes the exact digest without rebuild and remains the final live
runtime acceptance gate. After Stage approval, `main` is fast-forwarded to the
same approved source commit. The release finalizer must then prove that:

- current `main` equals current `stage` and the requested source commit;
- source `VERSION` is exactly `3.1.6`;
- the requested release version is exactly `v3.1.6`;
- these release notes and the v3.1.6 QA checklist exist on that source commit;
- the successful Development Continuous Integration run and Stage promotion
  refer to the same source SHA and immutable image digest;
- live Stage reports the expected exact image; and
- Stage desired-state evidence matches the approved candidate.

Only then are GHCR/Docker Hub `3.1.6` and `latest` aliases copied from the
approved digest and the annotated `v3.1.6` tag and GitHub Release created.
Release publication is performed without rebuild or an additional CE production
deployment.

## Rollback

v3.1.6 introduces no schema migration or runtime contract change. Preserve the
normal matched backup, pin the previously approved v3.1.5 image/digest, and
verify health and routing before restoring normal traffic.

See the [v3.1.6 QA checklist](../v3.1.6-qa-checklist.md) and
[deployment/release guide](../deployment.md).
